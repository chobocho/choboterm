  • dialSSH에서 openPty 분리. 테스트: 목록 파싱·인자·Windows 인용, WSL 가짜 docker + 테스트 SSH 서버로 목록/동작/exec 탭/접속 유지 확인. 실제 Docker 서버·Docker Desktop에서는 아직 확인 못 함

2026-10-09 — 상용 대비 보강 5종

  • 점프 호스트(ProxyJump): 접속 창·세션 관리에 Jump 칸, ~/.ssh/config의 ProxyJump, Host 칸의 ssh -J. 여러 단계(a,b), none, 단계마다 config 별칭·키·known_hosts 확인, 점프 호스트 질문엔 단계 이름 표시. 기록·세션·내보내기에 저장. 실제 점프 서버 2단을 거치는 Go 테스트
  • 키워드 강조: error·fail·오류 빨강, warning·경고 노랑, success·성공 초록 배경(설정에서 단어 편집·끄기). xterm 데코레이션이라 출력·로그·프로그램 색은 그대로, 전체 화면 프로그램 제외. 화면 지우기(ED) 때 xterm이 마커를 폐기하며 데코레이션 목록 정렬이 깨지는 xterm 버그를 찾아 우회. Edge headless(DOM·WebGL)로 확인
  • 로그 줄마다 시각: [2026-10-09 21:30:15.123] 형식, 줄이 들어오기 시작한 시각. 일반 텍스트·원본 모두, 기본 켬
  • 이어받기 · 이어 올리기(SFTP·FTP): 받는 파일은 .part로 받았다가 완료 시 이름 변경, 남은 .part는 "이어받기 / 처음부터" 질문. 업로드는 이번 실행 중 끊긴 같은 파일만(옛 버전 오인 방지). 질문 창 버튼 이름 지정 기능 추가
  • 영어 화면: 설정 → 언어(자동 / 한국어 / English, 다시 시작 시 적용). 사전 i18n_en.json(약 470개) 하나를 화면과 Go가 공유. 화면은 MutationObserver로 나타나는 문구를 번역({} 자리·순서 지정·줄 단위), Go는 파일 대화상자·호스트 키 질문·터미널 안내·로그 표시. 정적 HTML 자동 점검으로 남은 한국어 없음 확인
  • 참고: 이 환경의 Bash 도구는 heredoc 안의 겹 백슬래시를 하나로 줄여서, 백슬래시가 든 스크립트는 Write 도구로 작성함

2026-10-09 — 내장 스크립트 언어 검토

  • 현재 매크로 기능을 확장하는 방향으로 Lua(gopher-lua)를 우선 추천. 순수 Go 구현이라 단일 실행 파일 배포에 맞고, 스크립트에 명시적인 터미널 API만 노출해 안전 범위를 통제할 수 있음
  • gopher-lua는 Lua 5.1 호환이므로 Lua 5.5 호환을 뜻하지 않음. 5.5 문법·기능이 필요하면 별도 VM 검토가 필요. 더 강한 제한과 결정성이 중요하면 Starlark도 대안. Python은 런타임·배포 부담 때문에 우선순위가 낮음
  • Racket·Scheme·Common Lisp를 비교: Scheme은 s7 같은 임베딩 지향 구현이 후보지만 Cgo와 Windows 빌드가 필요. Racket은 런타임·배포 부담, Common Lisp는 ECL 등 네이티브 런타임 통합 부담이 있어 Go 단일 실행 파일 배포에는 덜 적합
  • gopher-lua와 Starlark 모두 Go에 내장되는 라이브러리라 별도 런타임 배포는 없음. 실행 파일 증가량은 실제 링크 결과로, 메모리는 동일한 스크립트·API 작업 부하로 측정해야 하며 일반적인 고정 수치나 유의미한 우열을 단정하지 않음
  • QBASIC 포팅은 레트로 터미널과 잘 어울리지만, 전체 호환 인터프리터 구현은 문법·런타임 범위가 커 유지보수 부담이 큼. 실제 호환이 목적이 아니라면 SEND·WAITFOR 등 터미널 자동화에 필요한 제한된 BASIC 문법만 만드는 선택지로 평가
  • GW-BASIC도 같은 맥락으로 검토: DOS 시대 동작·환경까지 호환하려면 범위가 커 Go 앱에 바로 내장하기 어렵고, 터미널 자동화용 제한 문법을 새로 정의하는 편이 현실적
  • Lua와 Starlark를 모두 내장하는 것은 Go 구현끼리라 기술적으로 가능하지만, 공통 터미널 API·취소·시간 제한을 공유하고 엔진별 테스트·문서·예제를 관리해야 함. 초기에는 하나로 시작한 뒤 수요가 확인되면 두 번째 엔진 추가를 권장
  • 초기 스크립트 엔진은 gopher-lua 하나로 시작하고 필요한 표준 라이브러리와 터미널 API만 노출하는 방안을 권장. 이는 샌드박스·제품 범위 축소에 유리하지만 Lua 5.5 호환을 제공하는 것은 아님
