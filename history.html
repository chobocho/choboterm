2026-10-09 — 도커 기능 실제 Docker로 검증 (WSL)

  • WSL(Ubuntu 24.04)에 root로 docker.io(29.1.3)·openssh-server·리눅스 빌드 패키지(libgtk-3-dev, libwebkit2gtk-4.1-dev, pkg-config) 설치, chobocho를 docker 그룹에 추가, docker·ssh 서비스 켬
  • 테스트용 키(choboterm-test 주석)를 WSL ~/.ssh/authorized_keys에 추가. 컨테이너 ct-web(nginx, 8080) · ct-ubu(ubuntu, bash) · ct-log(busybox, 1초마다 로그) · ct-done(종료됨)
  • TestDockerLive(서버 쪽, 실제 SSH): 목록·공개 포트, bash 셸+창 크기, alpine은 sh, 로그 따라가기, 시작/중지/재시작, 없는 컨테이너 오류, 포워딩으로 nginx 페이지, SSH 탭 끊기면 컨테이너 탭도 종료 — 통과
  • TestDockerLocalLive(이 PC 쪽): Windows용 docker.exe CLI(작업 폴더에만)를 DOCKER_HOST로 WSL Docker에 연결해 ConPTY 셸·창 크기·sh·로그·재시작 — 통과. 테스트 동안만 dockerd를 127.0.0.1:2375에 열었다가 설정 삭제로 닫음
  • 발견·수정: Docker Desktop이 꺼져 있을 때 docker CLI 29의 문구("failed to connect to the docker API at npipe...")를 인식 못 해 원문이 나오던 것을 "Docker가 실행 중이 아닙니다"로. 서버의 권한 오류·데몬 꺼짐 문구는 실제로 확인해 단위 테스트에 추가

2026-10-09 — 도커 쪽 같은 문제 점검

  • 중복 없음: 컨테이너 탭은 저장·자동 시작이 없고 탭마다 셸 세션 하나(의도된 동작). 포트 열기는 ForwardAdd를 거쳐 같은 서버 탭에 대기로 공유되고, 대기 규칙도 "이미 있음"으로 봐서 다시 추가하지 않음
  • 보완: 컨테이너 탭을 연 원래 탭이 닫힌 뒤 Enter로 다시 열 때, 같은 서버(host·port)에 접속한 다른 탭이 있으면 그 탭의 접속을 사용

2026-10-09 — 포트 포워딩: 같은 서버 여러 탭 중복 수정

  • 원인: 규칙은 호스트별 저장인데 접속할 때마다 restoreForwards가 탭마다 모든 규칙을 시작
  • 수정: 같은 서버(host·port)의 탭 중 한 탭만 수신, 나머지는 "대기 (다른 탭에서 수신 중)". 수신 탭이 끊기거나 닫히면 대기 탭이 이어받음. 한 탭에서 추가·삭제하면 다른 탭에도 반영. App.fwdMu로 결정 과정 직렬화
  • 테스트 TestForwardOneTabPerHost: 탭 2개 수신/대기, 나중에 연 3번째 탭 대기, 1번 탭 닫으면 이어받아 실제 통신, 삭제 시 모든 탭에서 제거·수신 중지
  • 참고: V0.2.8 릴리스 직후 Pages 반영 확인은 중단됨(릴리스 커밋 빌드는 errored, 다음 커밋 빌드 진행 중이었음)
