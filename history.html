2026-10-08 — 배경만 반투명에서 GPU 선택

  • 질문: 앱을 두 개 띄우면 두 번째는 CPU만 쓰나 → 아님. debug.log상 GPU는 정상 감지, 배경만 반투명(settings.json 공유) 때문에 의도적으로 DOM 렌더러를 쓴 것. 먼저 떠 있던 옛 빌드는 반투명을 몰라 GPU 사용
  • 설정에 "배경만에서도 GPU로 그리기" 체크박스(glassGpu, 기본 꺼짐) 추가. 배경만일 때만 선택 가능, 바꾸면 바로 미리 보기·취소 시 원복. chooseRenderer가 glassOn() && !gpu일 때만 DOM 렌더러
  • 배경만 선택지의 "뒤가 흐리게" 문구 정정(흐림 없음), 안내 문구에 GPU 여부 표시. README 갱신
  • 실제 exe: 배경만 50% + GPU → 창 제목 GPU, 배경 비침(83,0,0) 동일, 탭 바·접속 창 불투명. 글자 확대 비교 시 GPU·브라우저 모두 읽기 좋음. settings.json 백업·원복, 띄운 PID만 종료

2026-10-08 — 반투명 버그 2건 수정

  • 버그 1: 창 전체 반투명이면 설정·질문 팝업까지 비침 → 레이어드 창(SetLayeredWindowAttributes) 대신 화면 안에서 #tabbar · #terms에만 CSS opacity 적용. 팝업·메뉴·검색 막대는 밖에 있어 불투명. 제목 표시줄은 Windows가 그려 불투명
  • 버그 2: 배경만 반투명이 적용 안 됨 → 사용자 debug.log 확인 결과 앱을 다시 시작하지 않아 꺼진 상태(glass=false)였음. 창을 항상 투명 가능하게 만들고(WebviewIsTransparent + WindowIsTranslucent, BackdropType None, 배경 alpha 0) 끄기일 때는 화면이 불투명 배경을 칠하도록 바꿔, 두 방식 모두 다시 시작 없이 바로 적용
  • 배경만일 때만 WebGL을 내리고 DOM 렌더러로 전환(chooseRenderer), allowTransparency도 테마보다 먼저 바꿔 즉시 반영. 배경만에서 보이던 xterm 기본 스크롤바 숨김. Go의 레이어드 창 코드(translucency.go, setWindowAlpha)와 BackgroundTranslucent 제거
  • 실제 exe 시험(settings.json 백업·원복, 띄운 PID만 종료, 빨간 창을 뒤에 둠): 창 전체 50% → 탭 바가 빨강과 정확히 반반, 접속 창은 (240,240,240) 불투명. 배경만 50% → 탭 바·접속 창 불투명, 터미널 배경으로 빨강이 비침. 끄기 → 검정. 설정에서 모드를 바꾸면 바로 바뀌고 취소하면 원래대로(모의 화면)

2026-10-08 — 반투명 (창 전체 / 배경만)

  • 설정 "색 · 커서"에 반투명(끄기 / 창 전체 / 배경만)과 불투명도 막대(20~100%) 추가. 막대·선택을 바꾸는 동안 바로 미리 보기, 취소하면 저장된 값으로 되돌림
  • 창 전체: WS_EX_LAYERED + SetLayeredWindowAttributes(window_windows.go setWindowAlpha), 100%면 레이어드 해제. 시작 시(domReady)에도 적용
  • 배경만: 시작할 때 WebviewIsTransparent + WindowIsTranslucent(BackdropType None)로 창을 만들고, 창마다 테마 배경을 rgba로 한 번만 칠함(xterm 배경·뷰포트는 투명, 여백은 창 안 padding). 다시 시작해야 켜짐. Acrylic은 비활성 창에서 회색으로 바뀌어 쓰지 않음. WebGL은 투명 배경에서 글자가 거칠어 이 방식에서만 DOM 렌더러 사용
  • 실제 exe로 시험: settings.json 백업 후 모드별로 실행·화면 캡처·픽셀 측정, 끝나면 원복(바이트 단위 일치 확인). 창 전체 50% → 뒤 색이 절반, 배경만 20/50/80% → 뒤가 80/50/20% 비침(133/83/33). 시험 창은 키보드를 뺏지 않게 SWP_NOACTIVATE로 위에 두고, 띄운 PID만 종료
  • 찾아 고친 것: 새 탭에 반투명 배경이 안 칠해짐(createTab에서 applyLook), xterm.css의 검은 뷰포트 배경
  • 기본값 off / 85% — 설정 테스트에 추가. README·도움말·소개 페이지 갱신

2026-10-08 — 허큘리스 테마 2종

  • 허큘리스(검은 배경 #000 · 녹색 글자 #33ff33), 허큘리스 반전(녹색 배경 #33cc33 · 검은 글자) 추가. 16색을 모두 녹색 계열 밝기 차이로 만들어, htop·mc처럼 배경색을 쓰는 화면도 읽히게 함. 테마는 12가지
  • Edge(Playwright)로 ANSI 16색과 색 배경 줄을 두 테마에서 확인. README·소개 페이지 갱신

2026-10-08 — 서버별 색 테마

  • 탭 우클릭 메뉴에 "색 테마 (이 서버)" 하위 메뉴 추가(마우스를 올리거나 클릭하면 열림): 기본값(설정 따름) + 10가지 테마, 색 견본과 현재 선택 ✓ 표시
  • 고른 테마는 접속 기록(hosts.json)의 그 호스트+포트 항목에 theme으로 저장. Go에서 탭의 실제 접속 대상(t.host/t.port)으로 찾으므로 ssh 명령형 입력·로컬 셸(포트 0)도 같은 키. 재접속·복제·분할·새 탭 접속 때 TabTheme으로 불러와 적용, 같은 서버의 다른 탭에도 즉시 반영. 접속한 적 없는 탭은 그 탭에만 적용
  • 창마다 배경색을 따로 칠하고, 터미널 주변 여백은 지금 탭의 테마 배경을 따름(paintMargin). history_store에 historyEntry / updateHistoryEntry 공통 함수로 정리, addHistory가 theme 유지
  • 테스트: TestTabThemeSavedPerHost. Edge(Playwright)로 busan 두 창 + seoul 탭에서 busan에만 Dracula 적용, 새 busan 탭도 Dracula 확인. README·도움말·소개 페이지 갱신
